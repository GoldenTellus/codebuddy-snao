# 上手（给装机器的人，不需要看代码）

装完以后，你手上有四样东西：

| 东西 | 在哪 | 干什么 |
|---|---|---|
| 管理员令牌 | `./snao token` | 调接口时用；相当于"你是管理员" |
| 审批台 | <http://127.0.0.1:7001/inbox> | **所有需要人拍板的事都在这** |
| 工作界面 | <http://localhost:13210> | 岛 01（LobeHub），人和 agent 干活的地方 |
| 一条命令 | `./snao status` | 谁活着、谁挂了 |

---

## 一、第一件事：看一眼系统活着没

```bash
cd codebuddy-snao
./snao status
```

期望：五个宿主服务全绿 + 岛 01 的 docker 全 Up。有红的就 `./snao logs <名字>` 看日志。

## 二、审批台：这套系统的心脏

打开 <http://127.0.0.1:7001/inbox>，你会看到"待决"清单。**这就是 SNAO 和普通 AI 工具最大的区别**：

> 凡是越过权限边界的事，不会自动发生，会停在等一个人点一下。

| 你在审批台能看到的 | 什么意思 |
|---|---|
| `authority` | 有人想用一个还没被授权的接口 → 点批准就永久放行 |
| `intake` | 有一条新知识想入库 → 批准它才进公司大脑 |
| `collision` | 新知识和已有知识**矛盾** → 你选哪条算数，备注必须写 |
| `disclosure` | 有人想看**别人的**资料 → 批准等于允许这一次披露 |
| `evolution` | 系统自己做了个改进提案 → 批准也不等于上线，还要走灰度 |

**三个规矩**（系统强制，不是提示）：

1. **拒绝必须写理由**——不写点不下去
2. **批准就是规则**——同类请求以后自动放行，不用再批
3. **全部留痕**——谁批的、什么时候、为什么，写在 journal 里，**不可改不可删**

## 三、加人 / 调岗 / 离职

不用改代码，也不用 curl：

```bash
node scripts/org.mjs list                  # 看现在有谁
node scripts/org.mjs teams                 # 看有哪些部门

# 加一个人
node scripts/org.mjs add --id lisi --name 李四 --team team-a --role employee

# 改角色（boss 老板 / manager 管理者 / employee 员工）
node scripts/org.mjs role --id lisi --role manager

# 调岗（原部门的知识立刻看不到）
node scripts/org.mjs move --id lisi --team team-b

# 离职（停用不删档，权限即时清零）
node scripts/org.mjs leave --id lisi
```

**角色只决定"标签"，范围由线算**：

| 角色 | 能看什么 |
|---|---|
| `boss` | 自己的 + 全公司 + 所有部门 |
| `manager` | 自己的 + 自己部门 + 他管的部门（`manages`） |
| `employee` | 自己的 + 自己部门 |

**注意**：`manager` 能管哪些部门看 `manages`，不是自动"所有部门"。

每次改动都会自动推给线（输出里的 `推给线：{...}`），权限当场生效，不用重启。

## 四、接企业微信（让人把文件发进来）

不配也能用，只是收不到文件。

1. 企微后台 → **智能机器人** → 新建一个（不是"自建应用"，是机器人）
2. 拿到 **Bot ID** 和 **Secret**
3. 填进 `deploy/.env`：

```
WECOM_AIBOT_ID=你的BotId
WECOM_AIBOT_SECRET=你的Secret
```

4. `./snao up`（会多起一个 `listener`）
5. 员工把这个机器人加到自己会话里，**把文件/图片发给它** → 自动进岛 03

资料进来之后会发生什么：

- **归属** = 消息的发送人（不是猜的，是企微给的）
- **可见范围** = 单聊就是他自己，群就是那个群
- **别人想看** → 停在审批台等你批（`disclosure`）

## 五、换岛（这是 SNAO 的核心承诺）

岛可以买、可以换。换的时候**线一行不改**：

```bash
./snao gate                              # 先跑闸门，确认现在是好的
node gate/bind.mjs pin 你的ID canary     # 先让一个人走新实现
node gate/bind.mjs canary --ratio 30     # 再放 30% 流量
node gate/bind.mjs status                # 看现在怎么分的
node gate/bind.mjs rollback              # 不对就立刻回滚（一行命令，不用重启）
```

## 七、常见问题

**Q：`./snao status` 显示某个服务不通**
`./snao logs <名字>` 看最后 40 行。多数是端口被占（改 `deploy/.env` 里对应的 `*_PORT`）或数据库没起来。

**Q：第一次调某个接口返回 `202` 和一段 `NEED_DECISION`**
这是正常的——去审批台批一次，之后同类请求自动放行。

**Q：客户资料存在哪**
`codebuddy-snao/data/intake/`，按内容哈希命名。**这个目录不进 git**，备份自己安排。

**Q：能不能两个人用同一台机器**
能。`deploy/.env` 里把 `COMPOSE_PROJECT_NAME` 和各 `*_PORT` 都改掉，就是完全独立的第二套。

**Q：怎么知道系统没在偷偷干坏事**
所有经过网关的动作都在 `journal` 表里，且有触发器禁止修改和删除。这就是"发生过什么"的唯一真相。
