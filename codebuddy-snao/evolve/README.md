# 进化提案（P4 第 3 项）

**铁律：进化只在沙箱跑，产出提案，不直接上线。**

```
候选变体 → 影子实例（独立端口 + 影子库）→ 评分函数打分
        → 提案文件（分数 + 风险 + 推荐）
        → 上呈线的 decision（reason=evolution）
        → 人裁 → 才可能经 UnitBinding 灰度上线
```

## 跑法

```bash
node evolve/propose.mjs        # 跑一轮，产出提案并上呈
node evolve/score.mjs http://127.0.0.1:7200   # 只给某个实例打分
```

| 文件 | 作用 |
|---|---|
| [`score.mjs`](score.mjs) | **评分函数**（由线提供）：拿评分集给任意岛 02 实例打分 |
| [`score-set.json`](score-set.json) | 评分集：15 条带正确答案的判定用例 |
| [`propose.mjs`](propose.mjs) | 起影子实例 → 打分 → 写提案 → 上呈线 |
| `proposals/` | 每轮产出的提案，都是"未应用"状态 |

可进化参数（只在岛 02，且只这几个）：`SNAO_DEDUP_THRESHOLD`、`SNAO_CONFLICT_ON`。

## 实测（2026-11-19）

| 变体 | 分数 | 失败的用例 |
|---|---|---|
| `online`（去重 0.8 / 矛盾开） | 0.967 | S-14 |
| **`dedup-strict`（0.9）** | **1.000** | 无 |
| `dedup-loose`（0.7） | 0.900 | S-09, S-14, S-15 |
| `no-conflict`（矛盾关） | 0.767 | S-02, S-05, S-06, S-08, S-09, S-12, S-14 |

产出：推荐 `dedup-strict`，但 `applied: false`，**线上仍是 0.8**；提案已上呈为 decision #17。

### 评分集自己也被修过两次

1. **第一版是满分陷阱**：12 条用例让所有去重变体都拿 0.917 —— 满分说明它分不出变体，进化没有信号。
   加了三条边界用例（只差一个合同编号 / 只差联系人的近重复 / 加了限定条件的近重复）才有区分度。
2. **阈值参数没生效**：`judge-one` 里还留着一处硬编码 `0.8`（替换时缩进没对上），
   导致 `dedup-strict` 和 `online` 分数一样。是"两个变体分数完全相同"这个异常暴露的。

### 顺带修掉的两个真缺陷

评分集 S-05 / S-06 一开始就失败，查出来是矛盾检测的两个硬伤：

- 值的正则只吃 `[\w.\-/]`，**中文值一律漏掉**（"项目负责人是张三" 判不出矛盾）
- 日期被截断（"2026年3月1日" 只取到年份 "2026"，于是"同日期不同月"判不出）

改成能吃到中文与日期整体后，S-05 / S-06 通过。
